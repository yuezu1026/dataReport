# dataReport 项目代码分析

> 分析日期：2026-08-12
> 仓库：https://github.com/yuezu1026/dataReport（master 分支，共 3 次提交）

## 1. 项目是什么

**dataReport 是一套跨境电商卖家 VAT（增值税）计算与报告系统**，面向在 Amazon（亚马逊）、eBay、英国本土电商等平台销售的卖家，帮助他们：

1. 上传平台导出的订单数据（Excel）
2. 按"业务活动周期"（月度）和"申报国家"自动汇总销售额
3. 按各国增值税税率（标准税率/低税率/初始税率）计算应缴 VAT
4. 自动生成带水印的《增值税报告》PDF，供下载留存/申报使用

项目是一个 **Java Web 单体应用**（war 包），核心业务在 `vat_computing` 子项目，另有 `vat_computing_test` 子项目（旧版/精简版）。

## 5. 核心业务流程

```
用户注册/登录（Shiro 认证 + 角色权限）
        │
        ▼
导入平台订单 Excel（Amazon / GB / eBay 三套，异步任务）
   ├─ 删除该用户旧数据 → 插入新订单
   ├─ 生成导入批次号（import_batch）
   └─ 自动提取"业务活动周期"（月份）写入 user_activity_period
        │
        ▼
VAT 计算（按用户勾选的申报国家 + 周期月份）
   ├─ ① 按 A/B/C 类型汇总含税销售额 → 中间结果表 vat_computing_middle_result
   ├─ ② 取国家税率（标准/低/初始）→ 汇率换算（exchange_rate）
   └─ ③ 算税金 → 结果表 vat_computing_result
        │
        ▼
生成《增值税报告》PDF（iText，带水印，按报告号归档）
        │
        ▼
用户在线预览 / 下载 PDF（vat_pdf_result 记录）
```

### 5.1 VAT 计算公式（ComputingAmazonServiceImpl/ComputingGBServiceImpl）

- **中间结果**：按 `transaction_currency_code` 汇总 `total_activity_value_amt_vat_incl`（含税销售额），区分三种计税类型：
  - **A 型**：`sale_depart_country IN 征税国家`（发货国在征税国名单）
  - **B 型**：`sale_arrival_country NOT IN 用户勾选国家 AND IN 征税国家`（到达国不在用户勾选范围）
  - **C 型**：`sale_arrival_country IN 征税国家`（发货国交税模式，当用户配置 `computingMethod != "1"`）
- **汇率换算**：目标国币种与订单币种不同时，按 `exchange_rate` 表当月汇率折算；目标国为 `from` 则取 1/rate，为 `to` 则取 rate。
- **税金计算**：
  - 使用标准税率时：`税金 = 含税销售额 / (1 + 标准税率) * 标准税率`（价内税，英国式）
  - 使用非标准税率时（GB 的 init/low）：`税金 = 含税销售额 * 税率`
  - GB 国家额外支持税率类型选择：`taxRate=init`（初始税率）/ `low`（低税率）/ 其他（标准税率）
- **结果落库**：`vat_computing_result` 保存含税金额、不含税金额、税金、币种、周期。

## 9. 遗留问题 / 半成品

1. **微信支付模块未完成**：MainAction 统一下单逻辑、WeiXinController.getQrCode 均被注释/空实现，微信回调 servlet（WeiXinUtils）仅注册未接业务。

3. **根目录冗余文件**：`OrderAmazonMapper.xml` 与 resources 下重复；`README.md` 为空。
4. **安全隐患**：数据库明文密码入库；Shiro 配置旧版 1.2.5；上传目录硬编码 `E:/vat_computing/...`。
5. **代码风格**：Java 1.7 语法 + 大量 raw type Map 传参，维护成本高。
