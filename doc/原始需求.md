# dataReport 原始需求（逆向还原）

> 说明：本文档由 `doc/代码分析.md` 及源码**逆向还原**，站在立项/业务视角描述"这套系统当初想解决什么问题、要做什么"。部分细节（如具体申报国家名单、费率数值）代码中仅有占位/逻辑，标注为【推断】。
> 还原日期：2026-08-12

## 1. 背景与痛点

跨境电商卖家在 Amazon（亚马逊）、eBay、英国本土电商等平台销售商品，面临欧洲各国增值税（VAT）申报问题：

1. **多平台多国**：订单分散在多个平台、发往多个国家，每个国家税率不同，手工汇总工作量大。
2. **平台数据格式复杂**：平台导出的订单 Excel 字段多（Amazon 单条订单 80+ 字段），人工整理易出错。
3. **计算规则专业**：VAT 有"发货国交税""到达国交税"等不同模式，含税价/不含税价换算、多币种汇率折算，普通卖家难以准确计算。
4. **申报需要正式报告**：申报/留存需要带报告号、计算日期的正式增值税报告文档。

**一句话需求**：让卖家"上传平台订单 Excel → 系统自动算好 VAT → 下载正式报告"。

## 2. 目标用户

| 角色               | 描述                                          | 核心诉求                             |
| ------------------ | --------------------------------------------- | ------------------------------------ |
| 卖家用户（前台）   | 在 Amazon/GB/eBay 有店铺、需要申报 VAT 的卖家 | 快速导入订单、准确计税、下载报告     |
| 系统管理员（后台） | 平台运营方                                    | 审核卖家账号、查看用户、管理系统配置 |

## 3. 核心需求（用户视角）

- 作为卖家，我要注册账号，经管理员**审核通过**后才能登录使用。
- 作为卖家，我要上传平台导出的订单 Excel（Amazon / GB / eBay 三类），由系统解析入库。
- 作为卖家，我要**勾选需要申报的国家**（有 VAT 税号的国家名单中选取）。
- 作为卖家，我要选择**业务活动周期**（如"2018-01"），系统按周期 + 国家计算应缴 VAT。
- 作为卖家，我要能选择**计税方式**（A/B 分型计算 或 发货国交税模式）。
- 作为卖家，我要能生成并下载带报告号、水印的《增值税报告》PDF。
- 作为卖家，我要能分页查看已导入的订单数据。
- 作为管理员，我要能审核/驳回卖家注册申请，查看用户列表。
- 作为管理员，注册需通过**短信验证码**校验手机号。

## 5. 业务规则（从代码反推）

1. **审核前置**：卖家登录前需 `pass_flag` 审核通过（UserMapper 中 pass_flag 字段 + 登录校验）。
2. **导入即覆盖**：每次导入会 `DELETE` 该用户旧订单后全量插入（order_header/gb_order_header/ebay_order_header）。
3. **计税类型**（Amazon/GB 通用）：
   - **A 型**：发货国 ∈ 征税国家名单；
   - **B 型**：到达国 ∉ 用户勾选国家 且 ∈ 征税国家名单；
   - **C 型**：到达国 ∈ 征税国家名单（用户计税方式 ≠ "1" 时采用，即"发货国交税"模式）。
4. **汇率**：`exchange_rate` 表按周期存 from/to 币种汇率；目标国币种=from 时用 `1/rate`，=to 时用 `rate`。
5. **税金**：标准税率走价内税公式 `税金 = 含税销售额 / (1 + 税率) × 税率`；GB 支持非标准税率（init 初始税率 / low 低税率）走 `税金 = 含税销售额 × 税率`。
6. **周期格式**：活动周期形如 `2018-JAN`（英文月份缩写）或 `2018-一月`，系统换算为 `201801` 用于展示。
7. **报告**：每份报告有唯一报告号、计算日期、用户账号、申报国家，PDF 加图片水印与页眉信息。

## 6. 非功能需求（推断）

- **性能**：订单 Excel 可能很大（10MB+，单文件上限配置为 100MB），导入采用**异步**处理避免阻塞页面。
- **安全**：用户密码 MD5 存储；Shiro 做登录态与 URL 权限；生产环境计划启用 HTTPS（cert/ + mykeys.jks 存在但配置被注释）。
- **可用性**：图形验证码 + 短信验证码防滥用；统一错误页。
- **部署**：war 包部署，按环境（dev/test/pro）切换配置；上传/下载目录独立配置。
