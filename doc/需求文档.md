## 1. 引言

### 1.1 目的
本文档定义"跨境电商 VAT 计算与报告系统"的功能、业务规则、数据、接口与非功能需求，作为验收与后续开发（补齐半成品、改造升级）的依据。

### 1.2 范围
系统覆盖：用户注册/审核/登录、平台订单 Excel 导入、业务活动周期管理、申报国家配置、VAT 自动计算、增值税报告 PDF 生成与下载、订单查询、管理员后台与系统配置、短信/图形验证码、微信（部分预留）。

### 1.3 术语
| 术语 | 含义 |
|---|---|
| VAT | 增值税（Value Added Tax） |
| 业务活动周期 | 订单所属的税务期间，形如"2018-JAN"，系统内换算为"201801" |
| 申报国家 | 用户勾选、需要计算 VAT 的国家 |
| 征税国家名单 | 系统维护的有 VAT 税号规则的国家（tax_no_country） |
| 含税销售额 | 订单中 `total_activity_value_amt_vat_incl` 汇总值 |
| 计税类型 A/B/C | 见 4.6 业务规则 BR-03 |

## 2. 总体描述

### 2.1 产品定位
面向跨境电商卖家的一站式 VAT 计算与报告工具：**上传订单 → 自动计税 → 出具正式报告**。

### 2.2 用户角色
- **卖家（前台用户）**：注册、导入、计税、下载报告、查看订单。
- **管理员（后台用户）**：审核卖家、查看用户、系统配置、短信验证注册。

### 2.3 运行环境
| 项 | 要求 |
|---|---|
| 运行时 | Java 1.7+，Servlet 3.1 容器（内置 Tomcat） |
| 框架 | Spring Boot 1.5.6、MyBatis + PageHelper、Shiro 1.2.5、Druid |
| 数据库 | MySQL（库名 `tax_computing`） |
| 部署形态 | war 包，支持 dev / test / pro 三环境 profile |
| 前端 | FreeMarker + JSP + jQuery；静态资源位于 webapp/ |

## 3. 功能需求

### FR-01 用户注册与登录（卖家）
- FR-01.1 支持用户名 + 密码注册，用户名全局唯一（注册时实时校验）。
- FR-01.2 密码以 MD5 存储（shiro SimpleHash）。
- FR-01.3 支持"记住我"（rememberMe）。
- FR-01.4 登录成功后会话保存用户对象，登录次数累加；退出清会话并跳转登录页。
- FR-01.5 登录页提供图形验证码（/code）。

### FR-02 用户审核
- FR-02.1 新注册用户 `pass_flag` 为未通过，禁止使用核心功能（登录校验）。
- FR-02.2 管理员在后台（system/userReview.do）审核通过/驳回，可修改角色（t_user_role）。

### FR-03 订单数据导入
- FR-03.1 支持 Amazon（order_header）、GB（gb_order_header）、eBay（ebay_order_header）三类 Excel。
- FR-03.2 上传接口 `importExcel.do`，单文件上限 100MB（配置）。
- FR-03.3 导入为**异步任务**（ExecutorService + ImportOrderTask），导入期间前端可查进度。
- FR-03.4 导入前**删除该用户全部旧订单**，再全量插入新数据。
- FR-03.5 每次导入生成批次记录（import_batch：批次号、文件名、数据条数、完成状态）。
- FR-03.6 导入完成自动重建该用户的活动周期列表（user_activity_period）。
- FR-03.7 导入失败的 Excel 文件从上传临时目录清理。

### FR-04 业务活动周期管理
- FR-04.1 周期从订单的 activity_period 字段去重提取，支持多周期。
- FR-04.2 周期展示格式：`2018-JAN` / `2018-一月` → `201801`（英文/中文月份映射）。
- FR-04.3 用户可按周期执行计算（多选）。

### FR-05 申报国家配置
- FR-05.1 展示征税国家名单（tax_no_country），标记用户已勾选国家。
- FR-05.2 用户勾选保存后覆盖旧选择（先删后插，user_country）。
- FR-05.3 展示订单中的发货国/到达国分布（供用户判断计税范围）。

### FR-06 VAT 计算
- FR-06.1 按"用户 + 周期 + 申报国家"执行，支持多周期批量。
- FR-06.2 分步：清旧结果 → 汇总中间结果（vat_computing_middle_result）→ 计算最终结果（vat_computing_result）。
- FR-06.3 汇总口径：按币种汇总含税销售额，分 A/B/C 计税类型（规则见 BR-03）。
- FR-06.4 汇率换算：非目标国币种按 exchange_rate 折算（规则见 BR-04）。
- FR-06.5 税金计算：标准税率价内税；GB 可选用初始/低税率（规则见 BR-05）。
- FR-06.6 结果含：含税金额、不含税金额、税金、币种、周期、申报国家，金额保留两位小数。

### FR-07 PDF 增值税报告
- FR-07.1 按"报告号 + 计算日期 + 用户账号 + 申报国家 + 明细表"生成 A4 PDF。
- FR-07.2 PDF 含页眉（"增值税报告"、"VAT-COMPUTING信息服务中心"）、水印、表格化明细。
- FR-07.3 支持中文字体（simhei.ttf）。
- FR-07.4 报告记录入库（vat_pdf_result：报告号、文件路径、创建时间），支持按用户分页查询与下载。

### FR-08 订单查询
- FR-08.1 用户分页查看已导入订单（order/listOrder）。

### FR-09 计税参数配置
- FR-09.1 用户保存计税方式 computingMethod（"1"=A/B 分型；其他=发货国交税 C 型）。

### FR-10 管理员功能
- FR-10.1 管理员登录/注册（用户名唯一）。
- FR-10.2 管理员注册需短信验证码（阿里云短信，校验手机号）。
- FR-10.3 用户列表、用户审核、角色分配。
- FR-10.4 系统级配置维护（system_config）。

### FR-11 验证码
- FR-11.1 图形验证码（登录页）。
- FR-11.2 短信验证码：发送（/system/sendSmsCheckCode.do）、校验（/system/checkSmsCode.do）。

### FR-12 微信（预留/半成品）【推断为原始需求之一】
- FR-12.1 生成官网二维码（已实现）。
- FR-12.2 微信支付统一下单、支付回调（**未完成**，见 7 遗留）。

## 4. 业务规则

| 编号 | 规则 |
|---|---|
| BR-01 | 卖家必须审核通过（pass_flag=Y）方可正常使用核心功能。 |
| BR-02 | 订单导入采用"先清后插"：导入即覆盖该用户该平台全部历史订单。 |
| BR-03 | 计税类型判定（Amazon/GB）：**A 型**：发货国∈征税名单；**B 型**：到达国∉用户勾选国家 且 ∈征税名单；**C 型**：到达国∈征税名单（当 computingMethod≠"1"，即发货国交税模式）。 |
| BR-04 | 汇率：目标国币种=from 时汇率取 `1/rate`；=to 时取 `rate`；换算不进位，精度 10 位小数（ROUND_HALF_DOWN）。 |
| BR-05 | 税金：标准税率 → `含税 ÷ (1+r) × r`（价内税）；非标准税率（GB init/low）→ `含税 × r`；金额保留 2 位小数。 |
| BR-06 | 周期唯一：同一用户同一 dataType 下周期不重复；重建周期时先清空旧周期。 |
| BR-07 | 报告号唯一，报告记录按用户隔离（下载时校验 pdf_id 归属）。 |

## 8. 验收标准（按代码现状）

1. 卖家可注册→等待审核→审核后登录→上传 Excel→勾选国家/周期→计算→生成并下载 PDF 报告，全链路可用。
2. 计算结果与 BR-03/04/05 公式一致（A/B/C 分型、汇率折算、价内税）。
3. 导入批次状态可查；重复导入覆盖旧数据。
4. 后台可审核用户、分配角色、发送短信验证码。
5. 微信支付相关需求**验收不通过**（未完成，属遗留）。
